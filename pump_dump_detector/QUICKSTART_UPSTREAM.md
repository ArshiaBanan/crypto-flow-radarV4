# راه‌اندازی — مرحله‌به‌مرحله، دقیق

این فایل جواب یه سؤاله: **الان دقیقاً چیکار کنم؟** برای توضیح کامل هر فاز و هر تصمیم طراحی، `README.md` رو ببین — این فایل فقط مسیر اجراست.

**یه نکته‌ی صادقانه قبل از شروع:** من (کلود) نمی‌تونم این سیستم رو خودم روی یه سرور زنده اجرا کنم و نگهش دارم — نه دسترسی اینترنت دائمی دارم، نه می‌تونم یه آدرس عمومی بهت بدم. کاری که می‌تونستم بکنم رو کردم: کل سیستم رو ساختم، تست کردم (۱۲۳ چک خودکار، همه پاس)، و یه اسکریپت نصب خودکار ساختم که بیشتر اصطکاک راه‌اندازی رو از بین می‌بره. از اینجا به بعد باید خودت (یا هر ماشینی که انتخاب می‌کنی) اجراش کنه.

---

## مرحله ۰ — پیش‌نیاز

پایتون ۳.۹ یا بالاتر باید نصب باشه. چک کن:
```bash
python3 --version
```
اگه نبود: از [python.org](https://www.python.org/downloads/) نصبش کن (روی ویندوز، موقع نصب حتماً تیک «Add Python to PATH» رو بزن).

---

## مرحله ۱ — نصب

### اگه روی مک/لینوکس هستی (یا ویندوز با Git Bash/WSL)

فایل‌ها رو توی یه پوشه بذار، بعد:
```bash
cd پوشه‌ی-پروژه
chmod +x setup.sh
./setup.sh
```
این اسکریپت خودش: یه محیط مجازی پایتون می‌سازه، پکیج‌ها رو نصب می‌کنه، تست‌های خودکار پروژه رو اجرا می‌کنه تا مطمئن بشه چیزی خراب نیست، و بعد یکی‌یکی برای هر کلید API ازت می‌پرسه (هرکدوم رو نداشتی Enter بزن رد شو).

### اگه روی ویندوز (بدون Git Bash) هستی

```powershell
cd پوشه-پروژه
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python tests.py
```
اگه آخر خط `RESULT: ... 0 failed, 0 crashed` رو دیدی، یعنی نصب درست بوده. کلیدهای API رو دستی توی `config.py` باز کن و مقابل هرکدوم بین `""` بذار (لیست کامل کلیدها و لینک هر کدوم پایین‌تره).

## مرحله ۲ — کلیدهای API، به ترتیب اولویت

**نکته‌ی مهم:** سیستم حتی با **صفر کلید** هم کار می‌کنه — فاز ۱ (حجم، دفتر سفارشات، Open Interest، فاندینگ) و فاز ۱۰ (رگبار سفارش، سنگین‌ترین سیگنال تکی با وزن ۰.۱۷) هیچ‌کدوم کلید نمی‌خوان، چون فقط از endpoint های عمومی بایننس میان. هرچی کلید بیشتر اضافه کنی، پوشش بیشتر می‌شه؛ ولی برای شروع لازم نیست همه رو یه‌جا جور کنی.

اگه `setup.sh` رو اجرا نکردی، این‌ها رو دستی توی `config.py` پر کن — به همین ترتیب، چون وزن بیشتر مال اولی‌هاست:

| اولویت | کلید | لینک | رایگان؟ | چی رو باز می‌کنه |
|---|---|---|---|---|
| ۱ | `TELEGRAM_API_ID` + `TELEGRAM_API_HASH` | my.telegram.org | بله | نصف سیگنال اجتماعی + Whale Alert (بخشی از whale_flow) |
| ۲ | `ETHERSCAN_API_KEY` | etherscan.io/apis | بله | نصف whale_flow (کیف‌پول‌های بایننس+OKX) |
| ۳ | `LCW_API_KEY` | livecoinwatch.com/tools/api | بله | نصف سیگنال خارجی |
| ۴ | `CRYPTOMETER_API_KEY` | cryptometer.io/api-manage | بله | نصف دیگه‌ی سیگنال خارجی |
| ۵ | `REDDIT_CLIENT_ID` + `REDDIT_CLIENT_SECRET` | reddit.com/prefs/apps (نوع: script) | بله | نصف دیگه‌ی سیگنال اجتماعی |
| ۶ | `SOLSCAN_API_KEY` | solscan.io/apis | بله | پوشش Solana (⚠️ تأیید مستقیم نشده، README رو ببین) |
| اختیاری | `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` | BotFather + @userinfobot | بله | هشدار پوش (جدا از ردیف ۱) |
| اختیاری | `COINGECKO_API_KEY` | coingecko.com/en/developers/dashboard | بله | بدون کلید هم کار می‌کنه، فقط سقف پایین‌تر |
| دستی | `TELEGRAM_MONITORED_CHANNELS` | — | — | یه لیست پایتونیه، توی `config.py` دستی پر کن: کانال‌های سیگنالی که خودت دنبال می‌کنی |

## مرحله ۳ — اولین اجرا (یه اسکن تکی)

```bash
source venv/bin/activate      # ویندوز: venv\Scripts\activate
python main.py
```
باید یه جدول توی ترمینال ببینی (حتی اگه خالی باشه، یعنی این لحظه هیچ کوینی سیگنال نداده — طبیعیه). یه فایل `scan_results.csv` و یه فایل `pump_dump_detector.db` هم کنار بقیه‌ی فایل‌ها ساخته می‌شه.

**اگه خطا دیدی:** اکثر خطاها یا کلید غلط/جاافتاده‌ست، یا اتصال اینترنت. کد طوری نوشته شده که یه کوین fail بشه کل اسکن رو متوقف نمی‌کنه — فقط warning چاپ می‌کنه و رد می‌شه.

## مرحله ۴ — اجرای دائمی

سیستم باید **همیشه در حال اجرا** باشه تا واقعاً یه پلتفرم alerting باشه، نه یه اسکنر یک‌باره. دو گزینه:

### گزینه‌ی الف: روی همین کامپیوتر (ساده‌تر، ولی فقط وقتی روشنه کار می‌کنه)

```bash
python main.py --loop      # ترمینال ۱ — هر ۱۵ دقیقه اسکن می‌کنه
python dashboard.py        # ترمینال ۲ — داشبورد روی http://127.0.0.1:5000
```
برای این‌که با بستن ترمینال قطع نشه، از `tmux` یا `screen` استفاده کن (مک/لینوکس)، یا صرفاً پنجره‌ها رو باز نگه دار.

### گزینه‌ی ب: روی یه سرور همیشه‌روشن (واقعاً شبیه یه «پلتفرم»)

اگه می‌خوای حتی وقتی کامپیوترت خاموشه هم کار کنه، باید روی یه سرور (VPS) اجراش کنی. دو تا گزینه‌ی واقع‌بینانه:
- **Oracle Cloud Always Free** — یه ماشین ARM رایگان همیشگی می‌ده (الان در حد ۲ هسته / ۱۲ گیگ رم، از اواسط ۲۰۲۶ کمتر از قبل شده)، ولی گرفتن ظرفیت توی بعضی منطقه‌ها این روزها سخته («Out of capacity»). اگه صبر و حوصله‌ش رو داری، کاملاً رایگانه.
- **یه VPS ارزون (Hetzner، DigitalOcean، …)** — حدود ۴ تا ۶ دلار در ماه، ولی مطمئن‌تر و بدون دردسر ظرفیت.

روی سرور: همین فایل‌ها رو آپلود کن، `setup.sh` رو اجرا کن، بعد `main.py --loop` و `dashboard.py` رو با `systemd` یا `tmux` به‌صورت دائمی روشن نگه دار. **نکته‌ی امنیتی:** `dashboard.py` عمداً فقط روی `127.0.0.1` گوش می‌ده (نه کل شبکه) — اگه می‌خوای از گوشی هم بهش دسترسی داشته باشی، یا از طریق SSH tunnel وصل شو، یا قبل از باز کردنش به بیرون حتماً یه لایه‌ی authentication روش اضافه کن؛ همون‌طور که الانه، هرکسی که IP سرور رو بدونه و پورتش باز باشه می‌تونه بدون رمز بهش برسه.

## مرحله ۵ — تأیید این‌که واقعاً کار می‌کنه

بعد از چند روز اجرای `--loop`:
```bash
python backtest.py --confluence CONFIRMED
```
این نشون می‌ده سیگنال‌های CONFIRMED تا الان واقعاً چقدر درست از آب دراومدن (نرخ برد، میانگین سود). بعد از چند هفته:
```bash
python backtest.py --lift
```
نشون می‌ده کدوم فاکتورها واقعاً دقت رو بالا می‌برن — بر همین اساس می‌تونیم وزن‌های `config.py` رو با عدد واقعی تیون کنیم، نه حدس.
